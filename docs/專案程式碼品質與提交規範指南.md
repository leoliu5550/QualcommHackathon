# 專案程式碼品質與提交規範指南
[[ENG]](docs/ProjectDevGuidelines.md)
## 啟用 Git Hooks
我們使用 pre-commit 框架來自動管理所有本地檢查工具。
### 安裝步驟
1. 確保虛擬環境已啟動：
    ```bash
    source .venv/bin/activate
    ```
2. 安裝開發依賴 (包含 pre-commit 和所有檢查工具)：

這些工具都定義在 pyproject.toml 的 [project.optional-dependencies] dev 區塊中。
    ```bash
    uv sync --extra dev
    ```
3. 安裝 Git Hooks 啟動器： 運行以下命令，將檢查邏輯寫入您的本地 .git/hooks/ 目錄中：
    ```bash
    pre-commit install --install-hooks
    ```
## 本地自動檢查項目 (Pre-Commit Hooks)
一旦 Hook 安裝完成，每次您執行 git commit 時，以下檢查將會自動運行：
| 檢查 Hook    | 觸發時機     | 說明 |
|---------------|---------------|------|
| **ruff check** | pre-commit | 檢查所有 Python 檔案的程式碼風格（Linting）、潛在錯誤和規範問題。 |
| **ruff format** | pre-commit | 自動將程式碼格式化為標準風格。（請在提交前檢查並接受其變更！） |
| **bandit** | pre-commit | 對所有 Python 程式碼執行靜態安全分析，檢查常見的漏洞和不安全的程式碼模式。 |
| **pip-audit** | pre-commit | 使用 uv run pip-audit --local 檢查專案依賴項是否存在已知的安全漏洞。（使用 uv）自動忽略 pip 中的漏洞 GHSA-4xh5-x5gv-qwph，並跳過可編輯/本地套件。僅在 requirements.txt 變更時才執行。 |

- 手動觸發方法
```bash
ruff check
ruff format
uv run bandit -r . -c pyproject.toml --exclude tests 
uv run pip-audit --local --ignore-vuln GHSA-4xh5-x5gv-qwph --skip-editable
```

**注意**： 任何檢查失敗都會阻止提交。請修復問題後再重新提交。如果您需要暫時繞過 Hook（不建議），請使用 git commit --no-verify。

# 標準化提交訊息 (Commit Message)
我們使用 Commitizen (cz commit) 來確保所有提交訊息都遵循 Conventional Commits 規範（例如：feat: 增加檔案分類功能 或 fix: 修正讀取權限錯誤）。

推薦的提交方式
請不要使用傳統的 git commit -m "..."，而是使用以下指令：

```bash
cz commit
```
運行此指令後：

Commitizen 將引導您選擇提交類型（如 feat, fix, docs 等）。

提示您輸入主題和詳細描述。

生成符合規範的提交訊息。

訊息驗證 Hook
即使您手動使用 git commit，commit-msg Hook 也會自動運行，使用 cz check 來驗證訊息格式。如果格式不正確，提交將會失敗。

建議所有開發者一律使用 cz commit，以確保流程順暢。
